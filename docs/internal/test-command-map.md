# Test Command Map

| Command | Purpose | Requires Secrets |
| --- | --- | --- |
| `npm test` | Run the Node test suite (`test:js`). `pretest:js` first builds the Angular dist chain — the one `@openreceive/*` import under `tests/` with no tsconfig `paths` entry. | No |
| `npm run check` | Run the fast local gate: `validate` (JSON/schema/vector/provider validation plus generated-doc-table freshness), then `scan:secrets`, then `scan:naming`. | No |
| `npm run test:ci` | Run the full repository gate: `test:ci:core` then `test:ci:release`. | No |
| `npm run test:ci:core` | Deterministic source gate, and exactly what `ci.yml` runs per push: `check`, lint, format check, workflow check, generated-model freshness, public-API surface check, typecheck, Vue and Svelte checks, dead-export check, JS tests, package smoke. | No |
| `npm run test:ci:release` | Release-shaped gate: build packages, Ruby tests, Python tests (`test:python`), demo container and release checks, the Rails example's currency-drift check, demo builds (Node demos plus the Rails Shakapacker bundle), client-bundle scan, standalone checkout check, docs build, the .NET plugin suite. | No |
| `npm run test:live` | Live NWC smoke against a real wallet (Node + Ruby). Never part of the deterministic gate. | Yes |
| `npm run test:e2e` | Playwright end-to-end suite: boots the node-express Buy a Button demo in `DEMO_WALLET=testkit` mode and drives real Chromium through all four framework tabs (lightning, swap + refund, remint, persistence). Run `npm run build:packages` first: the demo's vite server resolves `@openreceive/*` to the built dists, and a stale dist fails the boot with a missing-export error (CI builds before every run for the same reason). Server stdout is piped (demo boot / `on_paid`, OpenReceive INFO). `LOG_LEVEL=DEBUG` for more OpenReceive detail; `--headed` / `--ui` to watch the browser. Weekly full run in `demos.yml`. | No |
| `npm run test:e2e:smoke` | The lightning spec's React tab only, against node-express — the per-push `e2e-smoke` job in `ci.yml`. | No |
| `npm run test:e2e:smoke:fastify` | The same smoke spec against the fastify demo (`OPENRECEIVE_E2E_STACK=fastify`); the second step of the `e2e-smoke` job. | No |
| `npm run test:e2e:smoke:fastapi` | The same smoke spec against the FastAPI demo (`OPENRECEIVE_E2E_STACK=fastapi`): its Vite config spawns `uv run uvicorn` and proxies the API paths, so the harness command is unchanged. Needs `uv`. The third step of the `e2e-smoke` job. | No |
| `npm run test:e2e:smoke:php-plain` | The same smoke spec against the plain-PHP demo (`OPENRECEIVE_E2E_STACK=php-plain`): its Vite config copies the standalone checkout build into `public/openreceive/`, spawns `php -S` and proxies the API paths, so the harness command is unchanged. Needs PHP 8.2+ with `ext-gmp` and Composer (`composer install` runs on first use). The weekly `buttons-php-plain` job in `demos.yml`. | No |
| `examples/buttons/server/php-plain/bin/ci` | The plain-PHP example's CI (the Rails `bin/ci` twin for a host with no test framework): `composer validate`, `php -l` on every file, the catalog/artwork drift check, the shared-boundary check (no `shared/server-node` or React imports), then the stack booted in testkit mode and driven with curl through order → invoice → cross-site 403 → `/__testkit/settle` → `payments/check` → the paid order and its download. | No |
| `npm run release:composer:plan` / `release:composer:build` | Read-only Composer release plan (`Version.php` and the Laravel `~X.Y.Z` constraint against the root version, split repositories, whether each package is committed), and the build: one `git subtree split` branch per package under `release/composer/<pkg>/<version>` with the Laravel `composer.json` fix-up (path repository stripped), verified for a root `composer.json` with no `path` repository. `--snapshot` builds from the working tree. Publishing is `publish-composer.yml` (`packagist` environment); `release:composer:publish` is the maintainer-machine fallback. | No |
| `npm run test:orms` | Real-ORM adapter lane: knex, typeorm, and prisma each drive the payments repository through their `@openreceive/http` factory on sqlite (generates the Prisma client first). The per-push unit tests pin the factories against fakes; this proves them against the actual ORMs. Weekly `orm-adapters` job in `demos.yml`. | No |
| `npm run check:public-api` | Diff every publishable package's export surface against the committed snapshot (`tools/validate/public-api.snapshot.json`) — the gate behind the curated adapter/wrapper surfaces. Regenerate a reviewed change with `--update`. | No |
| `npm run check:vue` | Type-check the Vue wrapper with `vue-tsc`. | No |
| `npm run check:svelte` | Type-check the Svelte wrapper with `svelte-check`. | No |
| `npm run validate` | Contract/vector validation plus generated doc-table freshness (spec route/error tables, headless symbol inventory), the kernel-table cross-checks (OpenAPI and JSON Schema enums against `spec/data/kernel-tables.json`), and vector coverage per engine (`spec/test-vectors/coverage.json`). Vector validation runs here — there is no separate `test:vectors` command. | No |
| `npm run scan:secrets` | Scan public repo files for likely committed receive-only NWC codes and reject tracked env files. | No |
| `npm run scan:naming` | Fail on the two-word spelling of the product name in any tracked file; the name is `OpenReceive`, one word, everywhere. | No |
| `npm run scan:client-bundles` | Scan generated demo `dist` bundles for browser-side NWC markers after `build:demo`. | No |
| `npm run check:standalone` | Verify the standalone checkout build (`packages/js/elements/dist/standalone/`, the last step of `build:packages`): one self-contained ESM file with no imports or `require()`, registers `<openreceive-checkout>`, `MANIFEST.json` hashes and version match the tree and `package.json`, and the `scan:client-bundles` secret markers find nothing. | No |
| `npm run generate:models` | Regenerate the generated contract constants, kernel tables and the FixedFloat decision table from OpenAPI, AsyncAPI, `spec/data/kernel-tables.json` and `spec/data/swap-state-table.json` — into TypeScript (`core`, `http`, `node`), Ruby (`openreceive/generated/tables.rb`), C# (`packages/dotnet/.../Generated/OpenReceiveTables.cs`), PHP (`packages/php/openreceive/src/Generated/`) and Python (`packages/python/openreceive/src/openreceive/_generated/`). | No |
| `npm run typecheck` | Typecheck all JS/TS packages and the Buy a Button server/demo TypeScript. | No |
| `npm run test:js` | Run the Node test suite, including browser/react/elements/framework adapter contract tests and real Vue/Svelte/Angular wrapper mounts. | No |
| `npm run test:ruby` | Run the Ruby tests (glob-discovered per gem) against shared vectors and receive-only behavior. Each gem's own `rake test` also works from its directory. | No |
| `npm run test:python` | The Python engine (`packages/python/openreceive`) through `tools/ci/python-tests.sh`: `uv sync --frozen`, then pytest over every `tests/**/test_*.py` (vector conformance for every family the `python` coverage entry does not exclude, the HTTP golden files, the SQLAlchemy repository on SQLite — plus Postgres/MySQL when `OPENRECEIVE_TEST_PGSQL_URL` / `OPENRECEIVE_TEST_MYSQL_URL` are set — the testkit fixtures, the app over the fakes, the FastAPI router through `TestClient`, the CLI verbs, the NWC transport against an in-process relay), then `tools/conformance/python-crosslang.py`. Hard failure on an empty test glob. Needs `uv`. CI (`python-engine`) runs it on 3.10 and 3.13 with Postgres and MySQL service containers, then `ruff check`, `ruff format --check` and `mypy` over the package. Part of `test:ci:release`. | No |
| `examples/buttons/server/fastapi/bin/ci` | The Buy a Button FastAPI example's CI (the Rails `bin/ci` twin): `uv sync --frozen`, the stubbed-wallet tests over `openreceive.testing` (order → invoice → settle → download), the catalog/artwork drift check, the shared-boundary check (no `shared/server-node` imports) and `pip-audit` on the locked environment. What the per-push `fastapi-example` job and the weekly `buttons-fastapi` job run. | No |
| `npm run release:pypi:plan` / `release:pypi:build` | Read-only PyPI release plan (root version → PEP 440, `_version.py` drift), and the build: `uv build` into `.release/pypi/<version>`, the wheel-contents check (`unzip -l` for the CLI, the FastAPI binding, the Django migrations and static assets) and `twine check --strict`. Publishing is `publish-pypi.yml` (trusted publishing, `pypi` environment); `release:pypi:publish` is the token-based fallback. | No |
| `npm run test:php` | The PHP engine (`packages/php/openreceive`) through `tools/ci/php-tests.sh`: `composer validate` per package, `composer install` when `vendor/` is missing, every glob-discovered PHPUnit suite (an empty glob is a hard failure), then the cross-language harness `tools/conformance/php-crosslang.php` — every shared vector family through the production PHP functions. Needs PHP 8.2+ and Composer on `PATH`; the repository tests run on sqlite in memory and additionally against real servers when `OPENRECEIVE_TEST_PGSQL_DSN` / `OPENRECEIVE_TEST_MYSQL_DSN` (plus optional `_USER` / `_PASSWORD`) are set. | No |
| `npm run test:e2e:btcpay` | Playwright suite for the BTCPay plugin (`tests/e2e-btcpay`), in Chromium against the running regtest stack (`packages/dotnet/docker/up.sh`, then `e2e.sh` once to save an API key). Setup page, doctor, Lightning checkout, the swap component to "Invoice Paid", the refund form, the pill switch. `packages/dotnet/docker/browser-e2e.sh` runs it inside the official Playwright image on the stack's network. On demand only, never per push. | No |
| `npm run test:dotnet` | The BTCPay plugin's xunit suite (`packages/dotnet/BTCPayServer.Plugins.OpenReceive.Tests`): vector conformance for every family the `dotnet` coverage entry does not exclude, plus kernel tests against the in-process testkit wallet and fake provider. Prints a clear `SKIPPED` line (never a silent pass) without a .NET 10 SDK on `PATH` or the BTCPay submodule (`git submodule update --init --depth 1 packages/dotnet/submodules/btcpayserver`; or set `BTCPAY_SERVER_ROOT`). `-- --filter <expr>` narrows it. CI runs it in the `dotnet-plugin` job; `test:ci:release` includes it. | No |
| `packages/dotnet/docker/up.sh` then `packages/dotnet/docker/e2e.sh` | The BTCPay regtest end-to-end stack, entirely in Docker Compose: builds the plugin in the SDK image, starts bitcoind/NBXplorer/Postgres/two LNDs/a TLS Nostr relay/the testkit NWC service/the fake LSC provider/BTCPay 2.4.2, funds regtest, then `e2e.sh` proves a Lightning payment, a swap, a refund and the spend-capable refusal over HTTP. On demand only, never per push. `down.sh --volumes` wipes it. | No |
| `npm run test:live:ruby:nwc` | Optional Ruby live-wallet smoke. Reads `NWC_URI` from the environment or root `.env`, redacts the connection string, runs `get_info` when `nwc-ruby` is installed, and creates an invoice only with `OPENRECEIVE_LIVE_CREATE_INVOICE=1`. | Optional |
| `npm run test:live:python:nwc` | Optional Python live-wallet smoke (`tools/live-nwc-test/python-smoke.py`). Reads `NWC_URI` from the environment or root `.env`, redacts the connection string, runs the receive-only preflight over the relay through the in-repo transport, and creates an invoice only with `OPENRECEIVE_LIVE_CREATE_INVOICE=1` — the same opt-in as the Node and Ruby smokes. Part of `npm run test:live`. | Optional |
| `npm run test:live:php:nwc` | Optional PHP live-wallet smoke (`tools/live-nwc-test/php-smoke.php`). Reads `NWC_URI` from the environment or root `.env`, redacts the connection string, runs the receive-only preflight through the production `NostrPhpNwcReceiveClient`, and creates an invoice only with `OPENRECEIVE_LIVE_CREATE_INVOICE=1` — the same opt-in as the Node, Ruby and Python smokes. Skips clearly when `NWC_URI` is unset or the Composer dependencies are not installed. | Optional |
| `npm run check:generated` | Fail when any generated rendering (TypeScript, Ruby, or C#) or the compiled payment icons are stale. | No |
| `npm run check:demo-containers` | Validate the demo Dockerfiles, compose templates, root `.env` loading, ports, and secret boundaries — the Node demos, the Rails demo, and the `kind: "python"` demos (FastAPI, Django), whose Dockerfiles must install the engine from `packages/python/openreceive` and never bake `.env`. | No |
| `npm run check:release` | Validate release-readiness metadata, package versions, private package status, changelog coverage, that the BTCPay plugin's csproj `Version` matches the workspace release, and that the Python package's `_version.py` carries the PEP 440 form of it (both stamped by `release:prepare`). | No |
| `npm run check:workflows` | Validate GitHub workflow shape, read-only permissions, safe commands, SHA-pinned actions, and that publishing appears only in `publish-gems.yml` (`gem push`, `rubygems` environment) and `publish-pypi.yml` (`uv publish --trusted-publishing always`, `pypi` environment). | No |
| `npm run build:docs` | Validate the docs manifest and build the docs import/search artifact under `dist/docs`. | No |
| `npm run build:demo` | Build the Buy a Button demos. | No |
| `npm run test:package-smoke` | Pack every JS workspace package into local tarballs, assemble an offline temporary project, and import each package. | No |
| `npm run test -w @openreceive/example-buttons-rails` | The Buy a Button example's catalog/artwork drift check (`script/check-catalog-artwork.mjs`) — not its test suite. The suite is `bin/rails test`; `bin/ci` runs setup, the stubbed-wallet integration tests, the schema and catalog drift checks, the shared-boundary check and the gem audit, and is what the per-push `rails-example` CI job runs. | No |
| `npm run test:live:nwc` | Live wallet smoke harness. Reads `NWC_URI` from the environment or root `.env`, checks `tools/live-nwc-test/expected_capabilities.json` by default, then skips clearly when unset. Stops after preflight unless `OPENRECEIVE_LIVE_CREATE_INVOICE=1` — the same opt-in as the Ruby smoke, so one command means one thing on both engines. | Optional |
